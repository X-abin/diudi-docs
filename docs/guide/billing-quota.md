# 计费与额度

DouDi.ai 使用统一额度体系记录模型调用消耗。公开状态接口显示，当前站点开启了货币化展示，额度展示类型为 `USD`，默认额度换算单位为 `500000`，美元汇率字段为 `7.3`。这些值可能随平台设置调整，请以控制台和最新同步数据为准。

## 额度如何理解

平台公开数据中常见字段如下：

| 字段 | 含义 |
| --- | --- |
| `quota_per_unit` | 额度单位换算基数。当前公开值为 `500000`。 |
| `quota_display_type` | 额度展示方式。当前公开值为 `USD`。 |
| `display_in_currency` | 是否按货币方式展示额度。当前公开值为 `true`。 |
| `usd_exchange_rate` | 美元汇率字段。当前公开值为 `7.3`。 |
| `model_ratio` | 模型输入计费权重。 |
| `completion_ratio` | 输出 token 相对输入 token 的计费倍数。 |
| `cache_ratio` | 缓存命中 token 的计费权重。 |
| `group_ratio` | 用户组或模型池的附加倍率。 |

## 消耗通常由哪些因素决定

一次请求的最终消耗通常会受到这些因素影响：

- 选择的模型。
- 输入 token 数量。
- 输出 token 数量。
- 是否产生缓存读写。
- 当前账号所属用户组。
- 平台是否给某些模型配置了固定请求价格或特殊表达式计费。

公开价格接口中的 `model_ratio`、`completion_ratio` 和 `group_ratio` 是理解费用的关键。实际扣费以登录后 `Usage Logs` 和 `Wallet` 中的记录为准。

## 分组倍率

公开价格接口当前返回的分组示例：

| 分组 | 倍率 | 说明 |
| --- | ---: | --- |
| `Codex-Stable` | `0.5` | ×20Pro池，核心生产 |
| `Codex-Standard` | `0.2` | Plus池，基础生产 |
| `Claude-MAX` | `2.5` | 公开接口未返回说明 |
| `Claude-AWS` | `3` | 公开接口未返回说明 |

如果某个模型只对特定分组开放，你的账号必须拥有对应分组权限才能调用。

## 查看自己的余额和消耗

1. 进入 `Wallet` 页面查看余额、充值和额度情况。
2. 进入 `Usage Logs` 页面查看每次请求的模型、状态和消耗。
3. 当发现消耗异常时，先检查是否使用了高倍率模型、长上下文输入或大量输出。

## 控制成本的建议

- 日常测试优先选择低倍率模型。
- 长文本请求先压缩输入，减少不必要的上下文。
- 给测试 API Key 设置较低额度。
- 定期查看调用日志，及时发现异常请求。
- 在生产项目中记录请求 ID、模型名和业务场景，便于对账。
